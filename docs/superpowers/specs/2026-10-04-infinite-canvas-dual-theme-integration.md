# ShuLan 无限画布双主题集成设计

## 目标

将 `D:\树懒AI\无限画布` 中的完整画布功能迁入 ShuLan Agent Kit，替换当前 `#/canvas` 的空状态页。迁移后保留 ShuLan 的主导航和应用外壳，并提供两个临时视觉入口，便于在同一份画布内容上比较、选择最终保留的设计语言。

## 用户体验

用户从左侧主导航进入“画布”后，首先看到两个入口：

1. **当前外观**：保留独立无限画布项目当前的视觉表现。
2. **ShuLan 风格**：功能和内容完全相同，但界面使用 Agent Kit 的思源黑体、语义颜色、间距、圆角、阴影和 Lucide 图标规范。

两个入口进入的是同一个画布实例。用户可在画布内切换主题，节点、连线、视口位置、媒体和本地保存内容不会重置。

## 架构

### 单一功能核心

无限画布的领域模型、Zustand 状态、任务服务、持久化、节点组件、媒体编辑和 React Flow 画布只迁移一份。新代码放在 Agent Kit `src/canvas/` 下，保留原项目的内部分层，避免与现有 Agent、创作、复刻和资产模块交叉依赖。

Agent Kit 的顶层 `App` 只负责路由和外壳组装，画布业务状态仍由迁移后的画布 store 管理。

### 双主题表现层

功能组件通过画布根元素的 `data-canvas-theme` 属性选择主题。共用的结构和交互样式只保留一份，当前外观与 ShuLan 外观仅覆盖颜色、排版和表面参数。

ShuLan 主题直接消费 `design-system.css` 和 `color-tokens.js` 的现有令牌，不再创建第三套设计变量。当前外观的专用令牌局部限定在画布根元素内，不污染其他 ShuLan 页面。

### 路由与入口

- `#/canvas`：双入口选择页。
- `#/canvas/original`：打开当前外观。
- `#/canvas/shulan`：打开 ShuLan 主题。

画布顶部提供一个紧凑的主题切换入口，使用户无需返回选择页即可比较。路由变化只改变主题，不重建画布业务数据。

## 功能范围

完整迁移原项目现有功能，包括：

- 文本、图片、视频和音频节点的创建与编辑。
- 节点选择、移动、连线、删除、撤销和重做。
- 缩放、重置、小地图与自动布局。
- 本地媒体、资产选择、提示词生成与任务状态。
- 图片处理、视频处理、剪辑与草稿导出。
- 画布快照迁移、本地持久化和异常降级。

原项目中明确禁用或尚未实现的能力（如真实云分享）不在本次迁移中凭空补齐。

## 数据与持久化

两个主题共用同一个画布快照和媒体存储。主题选择与画布业务数据分开保存：

- 画布快照继续使用迁移后的现有 schema 和版本迁移函数。
- 主题只保存 `original` 或 `shulan` 偏好，不进入画布快照。
- 从一个主题切换到另一个主题时，节点 ID、媒体引用和视口保持不变。

## 错误处理

- localStorage 不可用时继续以内存会话运行，不阻断画布显示。
- 本地媒体失效时在对应节点内显示可理解的空状态，其他节点仍可操作。
- 任务或媒体处理失败沿用原项目现有状态模型和重试入口。
- 无法识别的旧快照通过现有迁移层处理；不在 UI 组件内添加特例分支。

## 测试与验证

1. 先添加路由和主题切换的失败测试，再实现入口。
2. 迁移原画布现有单元和组件测试，确保迁移前后行为一致。
3. 新增同一快照在两个主题下渲染、切换后数据不变的回归测试。
4. 运行 Agent Kit 完整测试与生产构建。
5. 在浏览器中检查两个入口的桌面和窄屏布局、键盘操作、主题切换、节点创建、连线、持久化和媒体编辑。
6. ShuLan 主题检查实际字体为 `Source Han Sans SC VF`，并确认无外部字体请求或静态资源 404。

## 后续收敛

确定最终风格后，只需：

1. 将 `#/canvas` 直接指向保留的主题。
2. 删除选择页、主题切换控件和未保留的样式覆盖。
3. 保留全部功能核心、测试、画布快照和本地媒体数据。

这个收敛步骤不需要数据迁移，也不需要复制或重写画布功能。
