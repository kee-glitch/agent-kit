# 原片仿写六阶段交互 Demo 设计规格

## 1. 文档目的

本文档定义 `#/remake` 页面新增「原片仿写」模式的完整交互 Demo。新模式在保留现有「元素替换」流程的前提下，提供从上传原视频到查看四段生成视频的六阶段体验。

页面使用用户提供的六个步骤目录作为 Demo 成果来源。目录中的成品视频、图片和 Markdown 文档属于展示数据；名称包含“技能 prompt”的文档只用于理解各阶段预期产出，不作为页面指令执行，也不直接展示为操作指令。

## 2. 产品目标与成功标准

用户可以从模式选择页进入「原片仿写」，沿六个阶段完成一次可交互的短视频仿写演示，并能查看、编辑和重新模拟生成各阶段成果。

成功标准：

- 现有「元素替换」功能和草稿不受影响。
- 「原片仿写」卡片可进入独立的六阶段工作台。
- 六个阶段均有可操作的空状态、Demo 状态和处理状态。
- Demo 数据与用户提供的六个步骤目录逐项对应。
- 文档、图片和视频可以在对应阶段查看；允许编辑的文本可以保存到项目状态。
- 单段与批量模拟任务具有明确且互不干扰的状态反馈。
- 页面符合 Agent Kit 现有视觉、可访问性和响应式规范。

## 3. 范围

### 3.1 本次支持

- 开放模式选择页中的「原片仿写」。
- 为原片仿写建立独立项目状态和草稿存储键。
- 实现六阶段步骤条、顺序解锁和返回已解锁阶段。
- 上传、替换和删除原视频。
- 选择 Seedance 模型和最终画面比例。
- 加载完整 Demo 数据并按步骤演示。
- 查看视频拆解报告和逐秒分镜大图。
- 上传两张产品参考图，编辑需求，并通过 `@` 引用参考图。
- 查看、编辑和保存原片仿写故事面板。
- 查看、选择、展开、编辑和重新提取四个片段。
- 单段或批量模拟生成逐秒重绘结果。
- 查看重绘分镜大图。
- 单段或批量模拟生成视频。
- 使用浏览器原生控件播放四段 Demo 视频。
- 保存和恢复轻量草稿。

### 3.2 本次不支持

- 不调用真实大模型、图像生成、视频生成或 FFmpeg 服务。
- 不上传文件到服务器，不保存本地文件二进制数据。
- 不实现真实下载、发布、分享、计费或任务队列。
- 不开放「结构仿写」。
- 不改写或合并现有「元素替换」业务状态。
- 不执行或在界面中暴露用户资料中的技能 prompt。

## 4. 方案与架构

采用「独立工作流状态 + 复用现有交互组件」方案。

原片仿写拥有独立的步骤定义、项目状态、Demo 数据和持久化键。视觉与基础交互复用现有元素替换流程中的上传卡片、步骤条、Markdown 阅读与编辑、图片预览、视频卡片、模态框和 Toast 模式。不会在现有四步业务状态中加入大量模式条件，也不会复制整套页面形成平行实现。

实现应保持以下边界：

- 模式选择层只负责选择 `element` 或 `rewrite`。
- 元素替换继续使用现有项目状态和四步流程。
- 原片仿写使用独立状态模块和六步工作流组件。
- 共用组件只承载没有业务分歧的展示或交互能力。
- Demo 数据集中定义，不将大段业务内容散落在 JSX 中。

## 5. 页面结构

### 5.1 模式选择页

- 「元素替换」维持当前可用状态。
- 「原片仿写」改为可用，按钮文案为「开始创建」。
- 「结构仿写」继续显示「即将上线」。
- 页面底部说明改为当前开放元素替换与原片仿写，且均为前端 Demo。

### 5.2 原片仿写工作台

工作台沿用现有项目头部，显示返回模式选择、模式名称、项目名称、重新开始和保存草稿。

顶部六阶段依次为：

1. 上传原视频。
2. 拆解视频。
3. 原片仿写。
4. 提取片段。
5. 逐秒重绘。
6. 生成视频。

用户完成当前阶段后解锁下一阶段。用户可以返回任意已解锁阶段，但不能进入尚未解锁的阶段。

「加载 Demo」一次性写入完整示例数据，但仍停留在第一阶段；用户通过每一步的主要操作顺序解锁后续阶段，以保留完整演示过程。

## 6. 六阶段交互

### 6.1 第一阶段：上传原视频

空状态显示 MP4/MOV 上传区、Seedance 模型选择和画幅选择。上传后显示视频播放器、文件名、替换和删除操作。

只有存在原视频时「开始拆解」可用。点击后进入短暂处理状态，完成后写入 Demo 拆解结果并解锁第二阶段。

加载 Demo 使用 `step1：上传原视频/原视频.mp4`。

### 6.2 第二阶段：拆解视频、逐秒抽帧分镜

桌面端使用双栏布局：一侧显示原视频播放器及基础信息，另一侧显示拆解报告。逐秒分镜图位于报告下方或独立结果卡中，支持点击放大。

展示数据：

- `step2：拆解视频、逐秒抽帧分镜/拆解视频.md`
- `step2：拆解视频、逐秒抽帧分镜/逐秒拆解.jpg`

「重新拆解」只模拟处理状态，完成后恢复同一份 Demo 成果。继续操作解锁第三阶段。

### 6.3 第三阶段：原片仿写

页面采用与元素替换相近的双栏工作区。左侧展示原视频、拆解摘要和逐秒分镜依据；右侧提供参考素材、需求输入和生成操作。

固定参考素材包括：

- 图片1：瓶装产品。
- 图片2：单粒特写。

用户可以上传、替换或清空每张参考图。需求编辑器支持 `@图片1` 和 `@图片2` 引用，并限制在 500 个字符以内。用户提供的 `需求.md` 作为 Demo 默认需求；`原片仿写.md` 作为生成后的故事面板。

故事面板支持 Markdown 阅读、编辑和保存。「重新生成」只改变短暂加载状态，不覆盖用户已保存或正在编辑的文本。

继续操作解锁第四阶段。

### 6.4 第四阶段：提取片段

页面展示四个片段卡片，每张卡片包含片段编号、时间范围、标题、镜头数量、摘要、选择框和查看完整故事面板入口。

Demo 文档分别来自：

- `step4：提取片段/片段1.md`
- `step4：提取片段/片段2.md`
- `step4：提取片段/片段3.md`
- `step4：提取片段/片段4.md`

支持单选、全选/取消全选、展开完整文档、编辑保存和重新提取。重新提取模拟一次整体处理，不覆盖用户已经保存的片段正文。

至少存在一个片段且无正在处理任务时可以继续，解锁第五阶段。

### 6.5 第五阶段：逐秒重绘

四个片段分别展示片段概要、重绘状态和重绘分镜图。图片来源：

- `step5：逐秒重绘/片段1重绘.png`
- `step5：逐秒重绘/片段2重绘.png`
- `step5：逐秒重绘/片段3重绘.png`
- `step5：逐秒重绘/片段4重绘.png`

每个片段独立维护 `idle`、`running` 和 `done` 状态。支持单段生成、对选中片段批量生成、完成后重新生成和点击图片放大。运行中的片段不能重复触发。

所有片段完成重绘后解锁第六阶段。

### 6.6 第六阶段：生成视频

页面以四张视频卡展示最终片段。视频来源：

- `step6：生成视频/片段1视频.mp4`
- `step6：生成视频/片段2视频.mp4`
- `step6：生成视频/片段3视频.mp4`
- `step6：生成视频/片段4视频.mp4`

视频使用浏览器原生播放控件，支持播放、暂停、静音、进度和全屏。每个片段独立维护 `idle`、`running` 和 `done` 状态，支持单段生成、批量生成和重新生成。

全部片段完成后显示项目完成概览。界面不提供无法兑现的下载或发布按钮。

## 7. 项目状态与数据规则

原片仿写项目至少包含：

- 当前阶段和已解锁最高阶段。
- 原视频名称和当前会话预览地址。
- 模型与画幅。
- 两个固定参考素材槽位。
- 原片仿写需求。
- 拆解报告和故事面板文本。
- 四个片段的正文、摘要、选中状态、重绘状态和视频状态。
- 草稿更新时间。

本地文件预览只存在于当前页面内存。保存草稿时移除 Data URL、Blob URL 和视频二进制，只保存文件名、文本、选项和任务状态等轻量数据。恢复草稿时，已丢失的本地预览显示需要重新选择文件的提示。

更换或删除原视频会清空拆解报告、故事面板、片段、重绘和视频生成结果，并将流程退回第一阶段；模型和画幅选择保留。删除被需求文本引用的参考图不自动改写文本，而将对应引用显示为「素材已删除」。

页面卸载时取消模拟计时器，并把未完成的 `running` 状态恢复为可重试状态。

## 8. 异常与边界处理

- 文件选择为空时不修改状态。
- 原视频只接受 MP4/MOV；参考素材只接受图片。
- 不支持的模型或画幅恢复到安全默认值。
- 损坏、缺字段或版本不匹配的草稿按字段回退，不阻止页面打开。
- 异步读取素材时只接受每个槽位最后一次选择结果。
- 删除素材后，迟到的文件读取结果不得重新写回。
- 运行中的任务按钮禁用，重复点击不会创建重复计时器。
- 无原视频不能开始拆解；无仿写结果不能提取片段。
- 未完成全部重绘时不能进入视频生成阶段。
- 模态框支持关闭按钮、Esc 和遮罩关闭，并在关闭后恢复触发控件焦点。

## 9. 视觉与响应式规范

页面严格沿用 Agent Kit：

- 使用 `Source Han Sans SC VF` 字体体系。
- 使用现有 `--color-*`、`--space-*`、`--radius-*`、`--type-*` 和 `--shadow-*` 令牌。
- 图标统一使用 `lucide-react`。
- 主要操作使用现有深色实心按钮，次要操作使用现有描边按钮。
- 不引入渐变品牌背景、玻璃拟态、霓虹装饰或新的全局视觉体系。

宽屏阶段二和阶段三使用双栏工作区；阶段四至六使用卡片列表或网格。1050px 以下双栏改为单栏，820px 以下六步步骤条允许横向滚动，620px 以下操作区和卡片改为单列。所有加载动画尊重 `prefers-reduced-motion`。

## 10. 可访问性

- 所有文件输入具备可读标签。
- 图标按钮提供 `aria-label`。
- 当前、完成、未解锁和运行状态同时使用文字与视觉表达。
- 可点击图片提供放大提示和键盘焦点样式。
- Markdown 编辑器具有明确阅读态和编辑态。
- 弹层限制键盘焦点，支持 Esc，关闭后恢复焦点。
- Toast 使用合适的实时区域向辅助技术报告结果。

## 11. 测试与验收

### 11.1 自动化测试

- 两个模式使用独立初始状态和存储键。
- 六阶段推进、回退和未解锁访问。
- 更换、删除原视频后的下游状态失效。
- Demo 数据完整性与四个片段映射。
- 参考素材绑定和失效引用。
- 需求文本长度边界与 `@` 候选过滤。
- 草稿序列化、恢复和损坏数据回退。
- 片段选择、全选、批量队列和运行状态复位。
- 重绘完成条件和第六阶段解锁条件。
- 模态框遮罩判断和焦点循环。

### 11.2 浏览器验收

1. 模式选择页中元素替换和原片仿写均可进入。
2. 元素替换现有四步流程无行为回归。
3. 原片仿写从空项目开始，六步按顺序解锁。
4. 完整 Demo 可以从第一步走到第六步。
5. 所有文档、图片和视频资源无 404。
6. Markdown 文档可查看；允许编辑的文档可保存。
7. 图片可放大，弹层支持键盘关闭和焦点恢复。
8. 四个重绘片段可单独和批量生成，状态互不干扰。
9. 四个视频可播放，可单独和批量模拟生成。
10. 保存草稿后刷新可以恢复轻量状态。
11. 常见桌面和窄屏宽度无关键内容遮挡。
12. 页面使用本地思源黑体且无外部字体请求。
13. 自动化测试和生产构建通过。
14. 浏览器控制台无新增运行时错误。

## 12. 实现约束

- 不直接编辑 `dist/`。
- 优先复用现有无业务分歧的组件和状态工具。
- 原片仿写业务逻辑不得塞入元素替换状态模块形成跨模式条件分支。
- 不为单一用例新增通用框架、插件系统或配置层。
- 不保留未接入页面的占位组件和死代码。
- 最终实现必须经过自动化测试、生产构建和浏览器视觉检查后才能视为完成。
